## Round 1 deliberation and build recommendation

1. Integrate or work in an isolated checkout of the existing YUGA track instead of constructing a new shooter from unrelated native engines. Preserve ANDOLAN City Reform at its root. Branch inventories reveal substantial existing original game and art work.
2. Define the commercial quality aspiration as concrete interface targets: cinematic hero selection with an inspectable actual model, role/ability descriptions, legible team/objective status, crisp cooldown feedback, reliable settings/back flow and mobile input. Existing fourteen heroes and forty-two abilities give real content for those screens.
3. Use original YUGA assets and generated key art as distinct deliverables. AI images are visual direction; actual screenshots and runtime recordings must show implemented UI and models. Render the existing GLBs with Blender for inspectable asset review.
4. Install source-analysis/art tools outside the product dependency tree. Record source revision, license and whether fetched, built or actually executed. Select targeted probes; no stack benefits from running every unrelated engine simultaneously.
5. Round 2 should review the concrete UI/build diff and ordinary-input browser evidence, with one researcher checking flow/readability and another checking provenance/runtime limits. Require successful menu → hero → match → pause/settings → results/replay, plus reduced-motion/narrow-screen checks. Do not claim Overwatch parity from images or build success.

No product files were modified by this researcher. No Prometheus/OWLib binary, proprietary game data, model, sound or map was installed. The findings above are a concrete reuse plan, not an assertion that every listed engine was built or that the entire upstream codebase was audited.
