## Panel decision for the concrete launch improvement

Keep the actual live Rama portrait, indigo/ivory/worked-gold system, Noto fonts, two selected-practice controls and one primary launch action. The useful commercial-quality pattern is an immediately legible character, selected activity and objective with clear state feedback. A fabricated roster, online queue, rank or inventory would weaken the actual playable contract.

Add an original, concise briefing within the existing selected-mode decision area. Suggested factual content:

| Bow training | Learn Rama's bow and four abilities. | Courtyard targets; reset anytime. | Offline solo practice as Rama. |

Root may compress this into two rows if three duplicate existing copy or obscure the primary action. The briefing is presentation data; mode IDs and host intent signals remain unchanged. It must not launch scenes, grant abilities, resolve objective state, simulate loading or become a new mandatory confirmation screen. Use current remapped bindings for any added control hints; no new hardcoded default-key copy.

At 960×540 and enlarged text, keep readable fonts and use the existing deliberate vertical scroll/follow-focus path. The selected mode and keyboard focus remain different states. Preserve primary action, Help/Settings/Quit reachability, loading disablement, recovery copy and exact utility-opener focus restoration. The character should remain an actual rendered asset rather than become a generated full-screen menu painting.
