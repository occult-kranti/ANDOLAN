## Small control/state contract

Use semantic intents (`forward`, `back`, `left`, `right`, `interact`, `vehicle`, `menu`, `journal`, `horn`) with independent keyboard, touch and gamepad device state. Device adapters never directly decide mission rules. A single resolver reads the current session state and emits normalized continuous intent plus at most one discrete action per edge.

| State | Continuous movement | Discrete actions | Feedback |
| --- | --- | --- | --- |
| Title / connecting / disconnected | Neutral | Visible UI only; reconnect where applicable | Clear status and a direct recovery action |
| Playing on foot | Camera-relative move/sprint | Contextual interaction, enter nearby vehicle, menus | Next objective verb/place; current binding/device hint |
| Playing driver / passenger | Driver throttle/steer; passenger neutral | Stop/exit, handover or take-wheel if eligible | Driver/passenger role; brake versus reverse |
| Modal | Neutral immediately; world clock policy explicit | Native UI focus/activation only | Return to world restores meaningful focus |
| Binding capture | Neutral | Supported unique key; Escape cancels | Conflict/cancel explanation; current binding retained on failure |
| Hidden / blurred | Release all held state | None until resumed | Fresh input required; no delayed action replay |

Modal entry and reconnection are transitions, not another collection of independent flags. They clear held intent, pointer ownership and pending click edges once. Audio preview is separately bounded and user-triggered; it does not resume gameplay. Pending job acceptance is an operation state inside the board, not an optimistic change to the world.

## Fictional city decision presentation

Keep the new media/sector progression inside the existing City jobs surface: an authored in-world media ledger, four named sector milestones, and two explicit mandate choices after all work is verified. Label the feed fictional and gate discoveries by completed work. Each route names its mechanical reward trade-off and institutional consequence before voting; show connected crew count, matching-vote threshold and the player's current vote. An incoming snapshot updates this surface without forcing it open. The shared server state remains the authority for eligibility, votes, outcome and rewards.

## Implementation status

Baseline review complete. Moderator owns input/settings/audio-preview/CSS fixes; this reviewer implemented CityJobs pending acknowledgement, the authored media/sector ledger and mandate presentation. Findings above describe the pre-fix source. Browser/device verification and final release evidence are recorded by the integration owner.
