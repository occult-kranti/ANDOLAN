# Native screens and integration campaign

This campaign covers **five rounds of six screen assignments**, followed by **three rounds of six integration assignments**. These 48 assignments are separate from the three 15-role visual rounds. Six workers rotate through exclusive files; source imports and heavy captures have one owner.

The [execution ledger](SCREEN_CAMPAIGN.json) owns exact tasks and actual completion. Work starts with a clear launch choice, a real loading state and shared native controls. It continues through combat information, map/goal context, pause, guide, settings, results and recoverable errors. Available modes stay tied to implemented offline gameplay.

## Acceptance

Each round needs executed code or an independent finding, source hashes, relevant counterexamples and a review checkpoint. Changed screens require actual framebuffer review and exercised input paths. Headless assertions support those checks; they cannot establish visual quality or human game feel. Native window sizes and UI scaling are tested explicitly, rather than claiming browser reflow.

The implementation keeps Godot 4.6.3, Blender 4.3.2 and the existing 164-bone hero. It uses a shared indigo/gold/ivory hierarchy, readable labels, consistent 44 px primary controls, visible keyboard focus, bounded decorative motion and existing scene ownership. Source-backed book/open-code techniques enter only when they address an observed problem.

The final three rounds combine the accepted hero work with screens, stress state transitions and resource ownership, then qualify actual packages. Existing downloadable releases remain separate until a new source-matched package is verified and published. Deadlock is the quality target, not an achieved comparison.
