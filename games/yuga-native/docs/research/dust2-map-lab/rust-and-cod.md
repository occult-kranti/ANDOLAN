# Rust map research for the Dust II rebuild

**Verified November 26, 2026.** Rust can read the complete legacy CS:GO Dust II BSP that Valve distributes. The two readers we ran gave different answers on the same bytes. Use `vformats 0.1.0` for this file. Chimera is a working source-code reference for a Counter-Strike game and its world renderer. Its documented Dust II target is the Counter-Strike: Source edition. For Modern Warfare 2, IW4L and MW2WEB have readable Rust implementations of map loading, rendering and collision. An authored test floor below exercises their collision code. [Valve input manifest](source-evidence.json) · [Source reader](https://github.com/charles-mills/vformats/tree/a073bddf5af1714660c1313167ae3536f8a3262c/src/bsp) · [Chimera](https://github.com/r0pi0x/Chimera/tree/383d5913f2e1f58ce79401635164e175dc7eabea) · [IW4L](https://github.com/vladtrc/iw4L/tree/8fd4fb7adf84ae8170cc70628256d735815556ea)

The full BSP has SHA-256 `b91be410539fbbfc16300423f1e19c024f12addf1429c8cb2f72b53fe0fd6bcc`. The static-prop lump has 80-byte v11 records, 1,258 dictionary entries and 7,806 leaf references. A dictionary entry names a model, while a placement supplies its transform. The brush-model count includes worldspawn and 42 entity brush models. Each of the 8,324 displacement references resolves to a displacement record. Source face and vertex counts precede tessellation. A renderer still has to evaluate those grids and instantiate the referenced model meshes. [Probe implementation](probe/src/main.rs) · [Static-prop layout](https://github.com/charles-mills/vformats/blob/a073bddf5af1714660c1313167ae3536f8a3262c/src/bsp/game_lump.rs) · [World and displacement records](https://github.com/charles-mills/vformats/blob/a073bddf5af1714660c1313167ae3536f8a3262c/src/bsp/lumps.rs)

`vbsp` was mainly tested upstream on TF2 and CS:S. Its reader dispatches actual static-prop records for versions 4 through 7, 9 and 10. A v11 lump with zero records happens to pass, as the small community control demonstrates. Branch and content matter even with the same VBSP header. Switching readers preserved all 3,158 real placements. The sample OBJ converter processes the world model and selected faces. It is an example, with separate work needed to produce a complete scene. [Published reader source](https://docs.rs/crate/vbsp/0.9.2/source/src/data/game.rs) · [Converter](https://github.com/icewind1991/vbsp/blob/8f8ba5d92c4cd0ac15f25884d3bf5099d1f1bc37/examples/convert.rs) · [Upstream compatibility description](https://github.com/icewind1991/vbsp/tree/8f8ba5d92c4cd0ac15f25884d3bf5099d1f1bc37)

Run the locked probe with a local BSP. Additional arguments accept other VBSP files and Quake-family text maps. Its dependency checksums are in the lockfile. The full-map measurements above used Rust 1.100.0. [Dependency versions](probe/Cargo.toml) · [Checksums](probe/Cargo.lock)

```sh
cargo run --locked --manifest-path games/yuga-native/docs/research/dust2-map-lab/probe/Cargo.toml -- /path/to/csgo/maps/de_dust2.bsp
```

## Existing map geometry with explicit reuse terms

The downloadable archive contains both editable map files, the derived OBJ and MTL files, author credits and the upstream licenses. Blender 4.3.2 reopened both exports and counted every face reported below. [Download Atelier and Trident](open-geometry.zip) · [Verified local artifacts](build-receipt.json)

We downloaded and rebuilt two Xonotic maps whose authors grant GPL-3.0-or-later terms for the editable map sources. Both use curved patches that the Rust text reader rejected. NetRadiant's `q3map2` compiled both maps to Quake 3 IBSP and exported Blender-readable OBJ geometry. It tessellated all 1,525 patch definitions in Atelier and all 176 patches in Trident. This run used a source-map-only directory. Separate Xonotic texture, shader and model packages are needed for their original appearance. Reuse the editable map and applicable notices, track any added art under its own terms, and keep the corresponding editable source with a distributed derivative. [Atelier map and author](https://github.com/xonotic/xonotic-maps.pk3dir/blob/cc92d86adae0d8a795a3bf5634093593a86bdb53/maps/atelier.map) · [Atelier's license](https://github.com/xonotic/xonotic-maps.pk3dir/blob/cc92d86adae0d8a795a3bf5634093593a86bdb53/maps/atelier.license.txt) · [Trident map and author's license declaration](https://github.com/xonotic/xonotic-maps.pk3dir/blob/cc92d86adae0d8a795a3bf5634093593a86bdb53/maps/trident.map) · [Trident's license](https://github.com/xonotic/xonotic-maps.pk3dir/blob/cc92d86adae0d8a795a3bf5634093593a86bdb53/maps/trident.LICENSE)

The tested Linux compiler is NetRadiant-Custom release `20260114`, revision `68ecbed`. Its release archive SHA-256 is `f48f6f1d0db2b910ef9cb5dc5d8a722852510f3c5c278dc17615c0466b8a7a3d`. Set `q3map2` to the release executable and put either source map in `$xonotic/data/maps`. To reproduce the material-free geometry pass, use an empty Xonotic package root with the map files. Mount the game's content there for textured rendering. [Compiler release](https://github.com/Garux/netradiant-custom/releases/tag/20260114) · [OBJ exporter source](https://github.com/Garux/netradiant-custom/blob/68ecbed64b7be78741878c730279b5471d978c7c/tools/quake3/q3map2/convert_obj.cpp)

```sh
map_name=trident
"$q3map2" -meta -patchmeta -game xonotic -fs_basepath "$xonotic" -fs_homepath "$xonotic/privatehome" -threads 1 "$xonotic/data/maps/$map_name.map"
"$q3map2" -convert -format obj -game xonotic -fs_basepath "$xonotic" -fs_homepath "$xonotic/privatehome" -threads 1 "$xonotic/data/maps/$map_name.bsp"
```

We compiled the unmodified MW2WEB `clipmap_iw4` crate and supplied our own two-triangle floor. A six-unit descending ray hit triangle 0 at fraction `0.47916666`, normal `[0,0,1]`, surface flags `17`. The engine's 0.125-unit contact margin explains the hit just before the mathematical plane at 0.5. Moving the ray beyond the floor or reversing the triangle winding produced a miss. This exercises height, winding and material identity using the actual Rust collision implementation. None of these tests require commercial CoD art or a retail installation. [Fixture](probe/iw4-floor.rs) · [Pinned crate](https://github.com/bettertech-97/mw2web/tree/379c68231ebf54d01821ad096f4ac733ccca6d1b/crates/clipmap_iw4)

```sh
iw4_work=$(mktemp -d)
```

## Applying this to the ground-color experiment

1. Identify the edition and pair the exact BSP with its own NAV. The Valve 16.1 NAV records the matching BSP size. Its 1,118 areas include 26 named places and 74 individually unnamed areas. A stable area export retained all four Z heights. Those heights distinguish tunnel flooring from the ground above it. The CSV SHA-256 for this edition and basename `de_dust2` is `b9f7a1d5f764fbd461bba29fbe56c32243ff318d4113869b667d1f28f256aed3`. The Go fork retains the place names that the inspected Rust NAV SDK currently skips. [NAV export and commands](../../../tools/source-map-lab/nav/README.md) · [CoD-independent Source navigation reader](https://github.com/pnxenopoulos/csgonavparse/tree/354c86f749073e351a1e7d5474d9ef3ce9fedfc6) · [Rust NAV dialect and skipped fields](https://github.com/moonexpr/crabby-source-navmesh-sdk/blob/f580b6ab56587d0d6672aeac696ce1de57bc3148/src/format/nav.rs)
2. Compare the rebuilt world with the independent Rust face, displacement and placement counts. Use one model asset per resolved dictionary name and instance it at each placement. Materials and skins can vary by placement. Increasing a generic cube's size cannot recover model geometry.
3. Preserve per-triangle source material identity while tagging eligible ground. A single wall and a floor can share a source material. Surface normal, local NAV height, position and excluded surface types distinguish them. Keep render materials and collision data independently verifiable.
4. Keep a material-only before/after pair and compare topology, transform arrays and collision inputs. Use multiple fixed cameras at both sites and through tunnels to reveal accidental recoloring of wall faces. Any original Yuga map can reuse the tools, tests and classifier with its own meshes, surface art and game objects.

The survey used repository code searches for Rust `de_dust2`, GoldSrc WAD/BSP, Source `sprp`, Hammer VMF, `IW3`, `IW4`, `GfxWorld`, `ClipMap`, `d3dbsp` and browser/Wasm ports. The projects above were followed through their actual renderer, parser, supported header or test file. The recorded execution covers the BSP/NAV and text-map probes, both Xonotic geometry builds and the MW2 collision fixture. The list describes verified leads, without assuming every similarly named fork is a distinct game.
