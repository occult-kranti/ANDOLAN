# Open engines, shooter code, map tools and inspection resources

Task **YUGA-RESOURCE-AUDIT-2026-11-15** · native **YUGA · Sanctum** · reviewed **15 November 2026, America/New_York** (retrieval crossed into 16 November UTC). Repository baseline: `e59a07a4786e9ad491cfef7a4e706dbd06063adc`. This is source research supporting the existing Godot/Blender game, not an engine migration, downloaded asset pack, built dependency or accepted production-art packet.

The strongest near-term additions are **TrenchBroom + FuncGodot for an isolated original-map experiment, Godot's own samples for small implementation references, meshoptimizer for measured offline asset variants, and RenderDoc for our own rendered frames**. Network libraries belong to the later native-authority gate. Most complete open shooters are valuable references but would require a different codebase, content pipeline and licensing commitment to become a YUGA fork.

## What changed after checking the supplied catalog

1. **Open bomb-defusal and economy implementations do exist.** Hypersomnia advertises bomb defusal, and its pinned `arena_mode.cpp` contains planting/defusing outcomes, starting money and monetary awards. Its source also contains a buy menu. This directly contradicts the catalog's blanket statement that no open project implements those systems. It does not establish a ready-to-fork 3D 5v5 hero shooter, nor a permissively licensed Unreal implementation. [Mode source](https://github.com/TeamHypersomnia/Hypersomnia/blob/fd812be1053eaead68a06f30fd3717cfaa9a6caf/src/game/modes/arena_mode.cpp), [buy-menu source](https://github.com/TeamHypersomnia/Hypersomnia/blob/fd812be1053eaead68a06f30fd3717cfaa9a6caf/src/view/mode_gui/arena/arena_buy_menu_gui.cpp).
2. **Copyleft is not a ban on commercial use.** GPL permits commercial distribution while imposing corresponding-source and other obligations; AGPL adds a network-use source requirement for modified covered software. Whether incorporating particular code creates a covered combined work needs a component-specific review. “Study only” below is our adoption decision, not a claim that the license prohibits every commercial game. [ioquake3 standalone-game explanation](https://github.com/ioquake/ioq3/blob/52088b9eae247d8e321c8dc1fb49a879652854f9/README.md#standalone-game-licensing), [AGPL text](https://github.com/TeamHypersomnia/Hypersomnia/blob/fd812be1053eaead68a06f30fd3717cfaa9a6caf/LICENSE.md).
3. **Share-alike art is not automatically unusable in a store release.** CC BY-SA permits commercial use, but adaptation, attribution and restrictions on additional legal/technical barriers must be satisfied. Selecting CC0/CC BY first reduces integration work; it does not turn CC BY-SA into a noncommercial license. [Creative Commons explanation](https://creativecommons.org/licenses/by-sa/4.0/).
4. **Source availability and an open engine do not grant the original game's content.** ioquake3 expressly separates code from Quake III data. Source SDK permits a free modified Valve game on Source 1 under its conditions; that is different from the BSD-licensed GameNetworkingSockets library. AssaultCube's code and complete downloadable package have materially different terms. [ioquake3 README](https://github.com/ioquake/ioq3/blob/52088b9eae247d8e321c8dc1fb49a879652854f9/README.md), [Source SDK license](https://github.com/ValveSoftware/source-sdk-2013/blob/e1f1fd42271805072f052051c26c21caa2c87b04/LICENSE), [AssaultCube package terms](https://assault.cubers.net/docs/license.html).
5. **A viewer, parser or decompiler is not a recovered game.** ValveResourceFormat and FModel expose resource formats; Ghidra analyzes compiled programs. None supplies an absent production server, original authoring project, complete gameplay semantics or rights to ship extracted art. Our appropriate experiments use owned builds or separately cleared inputs. [Source 2 Viewer scope](https://github.com/ValveResourceFormat/ValveResourceFormat/blob/8facc4959e5b77f5ebc7b01e327cfa70fd200df0/README.md), [Ghidra scope](https://github.com/NationalSecurityAgency/ghidra/blob/42db038f3c88c6bd7e9bedbb919138111f8b77fd/README.md).
6. **Repository names and status matter.** `QodotPlugin/qodot-plugin` is the legacy Godot 3 project, while FuncGodot targets Godot 4. FreeHL's current checked README uses the name **Rad-Therapy**. The latter describes an independent QuakeC implementation; its clean-room label is an upstream claim, not an independent provenance audit by this research pass. [Qodot README](https://github.com/QodotPlugin/qodot-plugin/blob/4731a36dec690d37ef540af9b97727061c07473f/README.md), [Rad-Therapy README](https://github.com/eukara/freehl/blob/041a3fdcafec26e0bdde595e9b8f76caacbfd1fe/README.md).

## Practical adoption order and deliverables

This is an order among optional tool investigations, not the overall game-production queue. Finish the current Rama/Sangam art slice first; the shared adoption plan makes brush tooling conditional on a demonstrated map-authoring need.

| Order / owner | Bounded experiment | Acceptance evidence |
| --- | --- | --- |
| 1 · World artist + native integration | One original TrenchBroom corridor/site approach imported by a pinned FuncGodot into an isolated Godot project. Use only our own geometry and cleared textures. | Source `.map`, exporter/importer versions, material/entity mapping, scale/axis checks, actual traversal and reimport comparison. No canonical map replacement until reviewed. |
| 2 · World artist + build owner | One existing original static prop through the pinned meshoptimizer/gltfpack path, preserving the original. | Original/candidate hashes; triangle/material/texture metrics; uncompressed compatibility baseline; matched engine views; LOD transition and collision review. Record author cleanup time. |
| 3 · Native graphics owner | RenderDoc capture of our exact Rama/Sangam frame on the declared renderer. | Exact source/build/frame/settings, bottleneck observations and a bounded corrective hypothesis. Hardware timing is a separate physical-device experiment. |
| 4 · Rules + QA owner | Use Hypersomnia's documented bomb/economy behavior to construct independent YUGA edge-case questions. | Tests for simultaneous events, plant/defuse cancellation, round timeout, role swap, reward duplication and purchase validation. Preserve YUGA's original implementation and rules; no copied AGPL code is proposed. |
| 5 · Native authority owner | Compare current Godot transport against GNS/yojimbo only after selecting a concrete unmet requirement. | Two rendered clients and one authority; movement/hit/objective agreement; reconnect and loss/jitter cases; exact protocol and dependency notices. Local bot play remains offline. |

For every selected repository: resolve a release/commit; inspect that revision's license, notices, dependencies and file-level terms; download only the needed source or official build into a new scratch directory; record checksum and actual commands; build/import in isolation; then review the resulting artifact in the native game. A README build command, CI badge or downloadable binary is **upstream evidence**, not a local passing build. None of these upstream projects was installed, built, benchmarked or executed in this pass.

## Evidence and limits

The accompanying ledger resolves **26 repository commits** and records **52 immutable README/license fetches**, plus the targeted Hypersomnia and AssaultCube/Unvanquished source checks. GitHub connector reads succeeded, unlike the supplied catalog's earlier environment. Read scopes were selected descriptions, license clauses, compatibility and build sections; this was not a full source or dependency audit. Star counts were deliberately omitted as an adoption criterion. Commit timestamps describe checked branches, not the date of a tested release.

Initial failed lookups are retained in the ledger: an incorrect OpenArena repository URL, wrong license/README filenames later corrected, one transient AssaultCube repository-metadata failure, and unavailable GNU web pages. GPL/AGPL findings are supported by the immutable upstream license texts and ioquake3 explanation instead. No source claim depends on an unread GNU page. No screenshots, trailers, gameplay, extracted assets or upstream executable input were reviewed.

**Handoff:** changed files are this report and `engine-tool-sources.json`; baseline is the commit above. Checks are JSON/Markdown structure and link-shape review, not game tests. No runtime/assets/notices were changed because nothing was imported. Remaining dependencies are exact selected-file intake, Godot compatibility, artist/native review, chosen license architecture where relevant, and measured hardware/network experiments. Next owner: root integrates this research into shared README/roadmap/dashboard; subsystem owners execute the bounded candidates only when assigned.
