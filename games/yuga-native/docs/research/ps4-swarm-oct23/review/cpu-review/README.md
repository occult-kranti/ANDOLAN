# Independent CPU-helper review

Reviewed `cpu/reusable/cpu_llama.py` and `manifest.json`, the saved CPU receipts, the local CMake cache, pinned model card/license files, and the CPU/PS4 claims in the central draft. This review performed no downloads, builds, model inference, GPU tests or device connections. The reproductions use tiny temporary fixtures and mocked processes/HTTP; the only real external executable invoked was `curl --version`/`curl --manual`, with no URL.

## Findings

These findings concern the original source hash and are all resolved by the final independent correction check below. They are negative mocked checks, not evidence of a wrong-model response or escaped download in the actual recorded CPU run.

1. **P2 — ambient curl configuration can change the promised transfer policy** (`cpu_llama.py:64–68`). The command omits a leading `--disable`/`-q`; curl therefore loads its normal configuration before these arguments. The local curl manual explicitly documents this behavior. An isolated `CURL_HOME/.curlrc` containing a sentinel invalid option was read by `curl --version` and ignored by `curl --disable --version`. An ordinary existing configuration can enable `insecure`, extra URLs or retries, so explicit HTTPS scheme flags do not establish verified TLS and an exact single transfer on every machine. The final pinned size/SHA-256 still protects artifact acceptance; this finding does not imply a successful hash bypass. Put `--disable` immediately after the executable, retain the environment's supported CA/proxy configuration, and test that ambient curl configuration cannot change policy.

2. **P2 — a dangling partial-file symlink escapes the cache write boundary** (`cpu_llama.py:49–50, 59–81`). `Path.exists()` is false for a dangling symlink. A pre-existing `models/tiny.gguf.part` symlink to a nonexistent file outside the cache passes the guard; the output writer follows it, `checked_file` follows it, and rename promotes the symlink as a verified model. The mock reproduction wrote the bytes outside the cache and returned `VERIFIED`. A symlinked artifact parent directory permits the same boundary escape. Refuse artifact symlinks (including dangling ones), require output parent paths to resolve beneath the cache root, and create the temporary output exclusively without following symlinks. Do not indiscriminately reject normal virtualenv interpreter symlinks; constrain managed artifact/output paths.

3. **P2 — qualification does not establish that the expected model answered** (`cpu_llama.py:199–206, 234–248`). The initial port bind is closed before server startup, `/v1/models` is recorded without checking its identifiers, and the completion's `model` is never checked. A mocked health response followed by an unrelated model list/completion returned `REAL_INFERENCE_VERIFIED`. A different listener that wins the bind/start race can therefore supply the evidence before the owned server's next liveness check. Bind the HTTP exchange to this launch (for example, a fresh per-run API key supplied to the spawned server and requests), require the expected alias in inventory and completion, and check the owned process remains live. This is a negative unit-style reproduction, not evidence that a real competing listener was present. The independent content-quality field can appropriately remain separate from evidence that tokens were generated; current non-JSON output also yields exit success, so callers must gate usable-task qualification on `bounded_content_check_passed` explicitly.

4. **P2 — timeout/budget failures can leave a stale success receipt** (`cpu_llama.py:93–109`). An exception in the polling loop runs cleanup and then escapes before the JSON receipt is written. A mocked timeout terminated the child but left a prior `mock-build.json` with `exit: 0` unchanged. The CLI prints a failure, so this is an evidence/automation defect rather than a successful command exit. Write a new failure receipt in the cleanup path, including failure reason, final child exit and elapsed time, then re-raise. The analogous `check_budget` inside qualification's final receipt construction (`:262–266`) can also prevent a fresh qualification receipt from being saved.

## Boundaries and verified observations

- The initial review read an earlier `BLOCKED_NO_VERIFIED_WEIGHTS` receipt and HTTP 403/zero-byte transfer evidence. A later CPU-worker run replaced `qualification.json`: the first successful receipt finished at `2026-10-23T20:07:59.004156+00:00` and records `REAL_INFERENCE_VERIFIED`, 87 prompt tokens, 102 completion tokens, the expected alias in inventory and completion, and `server_stopped: true`. The model file now exists at 491,400,064 bytes. This review re-read and hashed the receipt; it did not rerun inference or independently hash the large weights. The build receipt's `inference_qualified: false` is a build-time field and is superseded for execution evidence by that later qualification receipt.
- The real completion fails the bounded task-content check: it wraps JSON in Markdown fences and uses a list for `steps` despite the requested short strings; its steps also include moving into the blocked tile. The current receipt correctly keeps `bounded_content_check_passed: false` separate from generated-token evidence. This run proves recorded cloud CPU generation, not a passing task fixture, reliable agent/tool behavior, PS4 performance or GPU execution. The mocked wrong-model finding does not describe this actual completion, whose alias matches.
- The local CMake cache has CUDA, HIP, Metal, OpenCL, RPC, SYCL, Vulkan and WebGPU disabled, plus `LLAMA_OPENSSL` and `LLAMA_SUBPROCESS` disabled. The manifest's `GGML_NATIVE=ON` produces a build for the cloud CPU; the central draft correctly warns against copying a laptop/cloud native build to the PS4.
- Both saved model-card and Apache-2.0 license files match their manifest sizes and SHA-256 values. This review did not newly retrieve either file or the model artifact.
- Transfer commands constrain initial/redirect schemes to HTTPS and check final artifact size/hash; the local API client bypasses proxies, rejects redirects and caps response size. The corrected helper disables ambient curl configuration before supplying its explicit transfer policy.
- The 3 GiB setting is a cache-footprint ceiling, not a filesystem free-space reserve. Download checks reserve the expected artifact bytes against that ceiling before transfer; build checks sample cache size during execution. Neither proves adequate free disk for the host or an instantaneous hard storage quota. Treat a `disk_usage(...).free` reserve check as useful additional protection unless the surrounding docs promise a reserve; absence of that extra check is not independently classified as a broken current promise.
