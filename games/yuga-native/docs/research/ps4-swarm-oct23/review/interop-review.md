# Independent build-farm review

Reviewed on 23 October 2026. Scope: the integrated `GAME_BUILD_FARM.md`; the job/quarantine helper; CPU build/download/qualification helper and manifest; PS4 inventory/source report; subscription-client study; and GPU/video access report. This review used source inspection and small temporary local or mocked reproductions. It made no device connection, network request, model download, model inference, GPU test or full-game run.

## Resolved findings and revalidation

All five findings below describe pre-fix versions and are now resolved on the versions identified after the table.

| ID | Severity | Original finding and consequence | Correction |
| --- | --- | --- | --- |
| C1 | P2 — resolved | `control.py` checks exact paths from the outer repository's `git ls-files`. A tracked gitlink only appears as its directory; a tracked binary underneath it is accepted as an untracked generated file. The local fixture in [cleanup-nested-git-reproduction.json](cleanup-nested-git-reproduction.json) demonstrates acceptance of a tracked `scratch/generated/component/asset.bin`. No quarantine was executed. | Reject candidates beneath tracked gitlinks and nested Git repositories, or explicitly query the owning repository before declaring a file untracked. Preserve the conservative source boundary. |
| C2 | P2 — resolved | The CPU downloader follows a dangling `.part` symlink, writes outside the declared cache and then promotes that symlink as `VERIFIED`. | Reject symlink components in managed artifact/output paths, including dangling links, and create partial output exclusively without following links. |
| C3 | P2 — resolved | CPU qualification records `/v1/models` and the completion model without validating either. The bind-check socket closes before server startup, so the HTTP exchange is not uniquely bound to the launched server. A mocked unrelated-model response was accepted. | Require the selected alias in both responses, check the owned process, and bind requests to this launch, such as with a fresh server API key kept out of receipts. This is a negative test, not evidence that the actual live run was misrouted. |
| C4 | P2 — resolved | The CPU downloader does not disable ambient curl configuration. An existing `.curlrc` can alter TLS, extra URLs or retries despite explicit HTTPS scheme flags. Artifact hashes still protect accepted bytes. | Put `--disable` immediately after `curl`; preserve the supported environment proxy and CA configuration. |
| C5 | P2 — resolved | `run_logged` cleans up after polling timeout/budget exceptions but skips saving a fresh result. A prior success receipt therefore remains. Qualification can similarly fail during its final budget computation before saving. | Save the new failure outcome, cause, final child exit and timing before raising. Do not leave a stale success file representing the latest attempt. |

## Checks that passed

- **SSH command transport:** job argv and workspace are JSON on stdin. Only the fixed bootstrap is quoted into the remote shell command. Target aliases reject option-like values; normal host verification is forced with `StrictHostKeyChecking=yes`; no password prompt is attempted. The matching helper hash and non-root remote user checks are present. A failed transport or malformed result records the remote outcome as unknown and directs inspection before retry. No actual SSH host was contacted.
- **Local execution and cleanup scope:** ordinary job argv use `shell=False`. The runner states that declared ownership and its GPU lock are cooperative, not an OS sandbox. Cleanup requires exact generated-file identity, rejects symlinks and protected client/configuration paths, preserves directly tracked paths, and quarantines rather than deleting. `freed_bytes: 0` is accurate. C1's nested-repository exception has been corrected and independently revalidated.
- **Hardware:** the laptop has 8 GB dedicated VRAM and separately reported 16 GB shared memory. The docs do not add these into 24 GB VRAM. Six roles share a qualified backend; task distribution is not model/tensor parallelism or pooled machine memory. Native cloud/laptop CPU binaries are not described as portable PS4 binaries.
- **PS4 evidence:** original hardware and the user's affirmative reply are retained with firmware, distribution, kernel, usable memory, GPU backend and SSH still unverified. The report does not infer CUDA, working ROCm or Vulkan inference from a graphics driver. The inventory defaults to no Vulkan exercise, performs no network request and needs no privilege escalation. Its status is syntax-checked, not console-executed.
- **Subscriptions and model routing:** supported client login is separate from API billing and actual plan eligibility. The cloud does not inherit laptop subscriptions or device access. Proprietary hosted weights are not supplied by a CLI. Local and hosted profiles are explicit, with no silent paid fallback. Responses, Anthropic-compatible and Chat Completions protocols are distinguished.
- **Sources, licensing and completion:** the PS4 forum was subsequently retrieved and its 15 posts read; historical self-reports remain distinguished from reproduced benchmarks. [Final PS4 source review](ps4-source-final.json) matched all 15 saved posts and 27 source/artifact hashes. The four videos still returned CONNECT 403 and remain unread; a running Space is not a GPU allocation or completed generation. CPU source/model licenses are identified separately from hosted subscription rights. Tool installation/qualification does not close game acceptance. The FG06 full native 3v3 gate remains explicit before 6v6, and desktop/Android campaign counts are preserved in the guide.

All substantive review findings are closed.
