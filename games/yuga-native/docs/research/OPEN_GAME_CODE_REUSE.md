# Open game code that can help the native hero slice

Reviewed 17 October 2026. **Reuse focused tools and small compatible modules; keep the current Godot/Blender hero pipeline.** Five source repositories were pinned, their code/data terms checked separately, and concrete movement, camera, networking, animation, pooling and tangent-attribute sections read. One unchanged OpenMW pool header was compiled and exercised in a separate GPLv3 research executable: **9/9 checks passed with AddressSanitizer/UndefinedBehaviorSanitizer and no sanitizer output**. No game engine, commercial client or artwork was imported into the native runtime by this audit.

The [source ledger](open-game-code-reuse.json) links immutable commits, file/section hashes, exact reading ranges and the [reproducible module check](../evidence/reuse-study/games/module-check/NOTICE.md). Thirty source/license/config files were fetched successfully. A wrong initial Valve camera path returned404; the pinned tree identified the correct `src/game/shared/` path. Two renderer files received only symbol searches and one OpenRA manifest was fetched without being read; these are labelled explicitly. This is a bounded source study, not five complete engine audits.

## Concrete sections and what to transfer

**Camera and traversal:** TF2's [third-person camera](https://github.com/ValveSoftware/source-sdk-2013/blob/be57e3d01ac7d7aa6a2cacbfef187c0b46616db0/src/game/shared/cam_thirdperson.cpp#L146) hull-traces toward the offset, retracts immediately near cover and interpolates recovery. Its [air movement](https://github.com/ValveSoftware/source-sdk-2013/blob/be57e3d01ac7d7aa6a2cacbfef187c0b46616db0/src/game/shared/tf/tf_gamemovement.cpp#L2101) has a grapple collision/step path, flattened input and server speed clamping. OpenMW's [camera update](https://github.com/OpenMW/openmw/blob/fa732a1551a696f8cb52a65c9896b8b4b92eb3dd/apps/openmw/mwrender/camera.cpp#L160) separately checks focal/ceiling clearance and camera distance. Adapt these as Godot SpringArm/shape-query acceptance courses: wall backing, shoulder offset, low ceiling, grapple arrival, moving surface, pause and teleport. Do not copy their coordinate axes, units or tuning into Rama without measurement.

**Movement and online state:** ioquake3's [movement owner](https://github.com/ioquake/ioq3/blob/87a99d18206e878a20289f05ac3c16005dcae5c3/code/game/bg_pmove.c#L2025) runs the same movement routine for client/server and subdivides long commands. Its active acceleration branch explicitly differs from a disabled alternative; a mature source tree still contains deliberate feel tradeoffs. The [network channel](https://github.com/ioquake/ioq3/blob/87a99d18206e878a20289f05ac3c16005dcae5c3/code/qcommon/net_chan.c#L304) rejects old/duplicate sequences and bounds fragment accumulation. Adapt stale/duplicate/reorder/oversized-input counterexamples to YUGA's existing protocol. These reads do not certify modern authentication, encryption or anti-cheat.

**Animation and input ownership:** Godot TPS [separates owning input from server application](https://github.com/godotengine/tps-demo/blob/a82f15448e9b015440d3bbdf5e10801b260c4e9f/player/player.gd#L38), chooses walk/strafe/aim states and spawns from a weapon marker. OpenMW's [animation selection](https://github.com/OpenMW/openmw/blob/fa732a1551a696f8cb52a65c9896b8b4b92eb3dd/apps/openmw/mwrender/animation.cpp#L877) uses explicit priorities, masks and named text-key times; [controller rebuilding](https://github.com/OpenMW/openmw/blob/fa732a1551a696f8cb52a65c9896b8b4b92eb3dd/apps/openmw/mwrender/animation.cpp#L1106) first removes old owners. Adapt a documented action/locomotion/face/secondary ownership policy and source-matched transition tests. Keep army-clock release and the existing single skeleton owner. The demo's root-motion authority should not silently replace YUGA movement rules.

**Pooling, with a measured counterexample:** the [OpenMW header](https://github.com/OpenMW/openmw/blob/fa732a1551a696f8cb52a65c9896b8b4b92eb3dd/components/misc/objectpool.hpp) reuses deque objects through a unique-owner recycling deleter. The standalone check proves reuse and safe duplicate/null reset, but also proves **payload is retained and there is no hard capacity guard**. Ten thousand fixed-concurrency borrows caused no further Item construction; this is not a frame-time benchmark or a claim of globally bounded memory. The owner must outlive borrowed pointers. YUGA already has bounded effect pools: retain explicit capacity, complete state reset, generation and retirement contracts rather than copying this general pool as a substitute.

**Do not assume demo code is finished game code:** the TPS [bullet lifetime branch](https://github.com/godotengine/tps-demo/blob/a82f15448e9b015440d3bbdf5e10801b260c4e9f/player/bullet/bullet.gd#L20) calls explosion after expiry and continues into movement/collision. A collision in that same invocation can reach another explosion call. This was a source-path observation, not an executed demo bug reproduction. Rama should preserve its existing exactly-once terminal-event tests. The demo also instantiates bullets directly; it is not evidence of a production pool.

**Replay diagnostics:** OpenRA's [order manager](https://github.com/OpenRA/OpenRA/blob/e180e3225f3930272dd451917467631618f8976f/OpenRA.Game/Network/OrderManager.cs#L147) processes disconnects on agreed ticks, checks exact frame numbers and compares world hashes. Its [recorder](https://github.com/OpenRA/OpenRA/blob/e180e3225f3930272dd451917467631618f8976f/OpenRA.Game/Network/ReplayRecorder.cs#L44) records a versioned session path and framed client payloads with disposal. Adapt version/epoch/tick/actor receipts and divergence artifacts. Defer a lockstep rewrite: native shooter prediction and two actual connected clients remain separate work.

**Rendering:** ioquake3's [BSP tangent call sites](https://github.com/ioquake/ioq3/blob/87a99d18206e878a20289f05ac3c16005dcae5c3/code/renderergl2/tr_bsp.c#L776), patch-grid flow and [animated tangent attributes](https://github.com/ioquake/ioq3/blob/87a99d18206e878a20289f05ac3c16005dcae5c3/code/renderergl2/tr_surface.c#L778) show that normals/tangent orientation belong to the model/render pipeline, including animation. The tangent helper implementation was not audited. Keep the current glTF/Godot renderer and root/performance's separately owned official MikkTSpace integration; this audit does not claim that integration is complete or that ioquake3's renderer was adopted.

## Next implementation packets

1. **Hero/camera:** implement only a measured gap from the camera course, then verify obstruction recovery and actual continuous aim/cast footage. Same-engine MIT references reduce API translation; they do not replace character sculpting, cloth, facial work or profiling.
2. **Native multiplayer:** extend the existing authority/replica bridge with a two-client course and tick-attributed divergence/replay records. Reuse library code only after its file-level license and API boundary are selected. A parser, a local replica fixture or an RTS lockstep source read does not close online play.
3. **Art tools:** accept root's pinned tangent-tool work only with original input/output hashes, notice, mesh/morph invariants and normal-map renders. Keep tool adoption distinct from claiming commercial-game reconstruction or target-quality art.

This audit adopts **no new game runtime code or game data**. Its only executed external game-code component is the isolated OpenMW header check under its own GPLv3 notice. Review the earlier [reusable systems](REUSABLE_GAME_SYSTEMS.md), [character audit](CHARACTER_REUSE_AUDIT.md) and [TF2 study](TF2_REUSE_STUDY.md) for their separately pinned scope. REA/fork capability is handled by the parallel analysis audit; public source availability does not mean those commercial games have been recovered here.
