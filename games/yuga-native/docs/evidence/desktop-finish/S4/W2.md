A separate keyboard restoration defect **did** reproduce. `close()` used only opener validity and visibility: it moved recovery focus onto a disabled opener or one queued for deletion. A focus-disabled opener also produced a real engine warning. [Unchanged-source counterexample](W2/guide-focus-before.json) passes27/29 and retains the warning in [raw output](W2/guide-focus-before-output.txt).

The narrow fix checks that a remembered opener is in the tree, visible, not retiring, focus-enabled and (for Buttons) enabled; it also rejects an explicitly disabled or retiring ancestor. A legitimately paused caller remains eligible. Close signals, selection/detail formatting, scrolling, effects persistence, keyboard handling and lifecycle scheduling retain their existing behavior. The guide does not choose a replacement focus target: it preserves the current caller/recovery owner when the old target is ineligible.
