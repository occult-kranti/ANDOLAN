## Reproduced cancellation ordering defect

A [bounded local replay of the unchanged end-to-end test](W6/e2e-focus-before/summary.json) passed boot, world entry and injected loading-error checks, then failed paused-world Return-focus restoration. Its keyboard path could no longer reach Return, and the 30-second local outer bound stopped it. The production 120-second catalog bound was not increased.

The caller restores explicitly processing UI children in `cancelled` callbacks. The loader had already restored its caller and attempted focus before those callbacks. Its legitimate disabled-owner guard rejected the still-disabled UI subtree; the world callback then restored processing without retrying focus. A new tiny fixture reproduces the same loss for queued cancellation, error/Escape and overlay disposal: [20/23 before](W6/cancel-focus-before/result.json), with no engine diagnostic.

The fix keeps weak opener/source references and the cancellation ticket. After callbacks, it retries focus only when no new attempt, active navigation owner, replacement scene or explicit callback focus supersedes it. The same eligibility checks reject hidden, detached, disabled, focus-NONE and queued-for-deletion controls. The retry is synchronous: no deferred focus task can steal later user input. No world/courtyard script edit was required.

The repaired fixture passes [23/23](W6/screens-cancel-repair/reports/ui-cancel-focus.json), including new-focus, replacement, detach, disabled, queued-deletion and reentry exclusions. The unchanged full end-to-end test passes [25/25](W6/screens-cancel-repair/reports/ui-end-to-end.json). Legacy boot, signals, host replacement and transition lifecycle suites also pass in that run.
