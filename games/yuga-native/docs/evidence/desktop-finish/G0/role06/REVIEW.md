# G0 — package and provenance integration

The package gate now accepts the deliberate schema-5 roughness stage while preserving the exact schema-4 notice and its original surface binding. The focused Python checks pass **504/504**: 287 historical provenance/font cases, 109 new schema-5/graphics payload cases, and 108 PCK security cases. Python compilation and whitespace checks also pass. Exact commands, source hashes and result files are recorded in [execution.json](execution.json).

`package-native.py` retains the fixed historical pins, formats the new dependency ledger for review, rejects symlinked source-directory ancestors, and requires the promoted infantry, environment finish, ability glyph and surface-binding scripts. Compiled scripts must have the correct remap destination. The masonry shader, G1 map manifest and both roughness texture descriptors/imported destinations must be present under their exact paths; filename decoys and orphan destinations fail. The optional upper-hair helper is not required or declared activated.

The existing `rama_package_cases.py --groom-review` accepts a complete schema-4 or schema-5 input. It copies only the validated source closure into a disposable fixture. For schema 5, it reconstructs schema 4 from the pinned historical notice **and its own old surface binding**, then runs every existing groom/cloth/nonhair adversary. It does not relabel the current surface script as historical. `traversal_security_cases.py` received additive fixture resources; its existing checks were retained.

The new `graphics_package_cases.py` challenges absent/substituted stages and fields, missing/tampered maps, descriptors, generator and parent notice, self-rehashed replacements, changed geometry/cloth ancestry, external file symlinks and an internal directory symlink. It also checks exact compiled-script and texture remaps, missing destinations, decoy names, duplicate/ambiguous bindings and restored valid inputs. Real production provenance inputs remain unchanged by the tests.
