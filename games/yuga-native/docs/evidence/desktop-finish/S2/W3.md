## Observed defect and correction

`RamaSurfaceFinish.report()` assigned each label's latest binding count to `profiles[label]`. The actual hero has several separate materials with the same label across its body, bow and LODs, so later bindings overwrote earlier counts. The old report summed to **19** even though direct traversal and `surface_slots` both correctly counted **46** finished slots. For example, gold reported 1 instead of 6 and skin 1 instead of 4. No actual surfaces were missing.

The one-line repair adds each binding's slot count to the existing label count. The [baseline counterexample](W3/lifecycle-r2-counterexample.json) fails exactly this new 25th assertion; the [repaired run](W3/lifecycle-r3-fixed.json) passes 25/25. Both logs contain zero engine errors or warnings. Exact source comparison proves this accumulation is the only runtime change; configure, release, profiles, textures, material values and geometry are unchanged.
