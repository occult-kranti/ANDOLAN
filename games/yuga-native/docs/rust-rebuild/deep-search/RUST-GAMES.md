# Rust games and browser ports

The most immediately portable module in this search was the MIT-licensed limiter from the Battlefront rebuild. It compiled independently and handled a stack of this project's actual ability cues. For graphics, Sandspiel offers a cell-update model for persistent visual effects, and the Vangers reconstruction offers a terrain-to-OBJ converter and a physics replay fixture. The table below identifies which upstream code was read. The audio probe and subsequent browser audio port are documented separately. [Runtime integration](AUDIO-PORT.md)

## Which projects run in a browser?

- **Iron Wolf** advertises a live browser implementation and a shareware scenario. The full game uses the player's own files. **Another World Suite** advertises a playable Rust/Wasm engine plus a debugger and resource viewer. Both launch pages responded successfully. [Iron Wolf](https://wolf.ironmule.dev/) · [Another World Suite](https://malandrin.github.io/another-world-suite/)
- **Un-Banished** exposes a browser setup flow for owners of Banished. **Shiloh** documents running the Wasm version from the player's own machine and source media. **qwasm2-rs** exposes an alpha browser port. Its README describes a separate demo PAK and local setup. Playback with original media was outside this test. [Un-Banished browser guide](https://tanepiper.github.io/unbanished/play) · [Shiloh setup](https://github.com/Asterber/shiloh/blob/e3dfde0d098b25135a5243839d44842ccbc5fe91/README.md) · [qwasm2-rs](https://athola.github.io/qwasm2-rs/)
- **Ruffle** runs Flash SWFs inside a Rust/Wasm player. Loading a title in that emulator is evidence about browser compatibility. It does not produce the title's game source or grant rights to its artwork. Its public player responded successfully. [Ruffle player](https://ruffle.rs/demo/)
- **Sandspiel** is an original browser simulation inspired by Powder Game. Its live site started in Chromium with two 300 × 300 canvases and the Sand, Water, Stone and Fire material controls. This is a relevant architecture for YUGA’s density-limited ground effect grid. [Sandspiel](https://sandspiel.club) · [Checked HTTP entry points](catalog/sites.json)

## A reusable module exercised with YUGA assets

We compiled the pinned `openbf` limiter as an independent Rust module, ran its upstream unit test, and created a second fixture from all six 24 kHz mono Hanuman trial cues. Two simultaneous copies of each cue make a deliberately crowded mix of 13,200 frames. Left input reached 1.193176 and would clip if directly clamped. Output peaked at 1.0, right/left linking error was 0, and lookahead delayed audio by 48 samples or 2 ms. Reducing source level to 8% preserved every sample exactly after that delay. The follow-up integrated the unchanged donor module into YUGA’s stereo Web Audio worklet. The ring scans its lookahead window for each sample, so the separate adoption report includes sample-rate CPU measurements and real browser audio tests. [Adoption and browser measurements](AUDIO-PORT.md) [Probe and reproduction](catalog/probe_limiter.py) · [Actual fixture hashes and output](catalog/limiter-receipt.json)

Run from the repository root with Python 3 and Rust 1.88 or newer. The command downloads one pinned Rust file, checks its digest, builds in a temporary directory and prints the measured values. Pass `--source PATH` for an offline copy.

```sh
python3 games/yuga-native/docs/rust-rebuild/deep-search/catalog/probe_limiter.py
```

## Next integration decisions

1. For lane bots, start with a YUGA obstruction and two simultaneous formation detours. Compare outcome stability with Genie’s slot-detour state and OpenBF's sweep probes. Keep the existing Rust collision boundary and original Confluence map.
2. For renderers, prototype a small VFX field from YUGA assets using Sandspiel’s local-neighbour update idea and once/loop timings from OpenInsaniquarium. Measure touched cells, GPU uploads and frame time against current per-cast visuals before replacing them.
3. For networking, use Tidewater’s seek/checkpoint scheme to test reconnecting an observer late in a match. Restore a YUGA snapshot, replay accepted commands and compare the resulting hash on both native Rust and Wasm.
4. For audio, profile recorded team fights and long sessions on target laptop hardware using the integrated Rust worklet. Compare audible headroom, clipping, latency, CPU and fallback behavior. The player bundle carries the pinned source’s MIT notice.
