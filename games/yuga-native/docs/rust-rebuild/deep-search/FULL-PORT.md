# YUGA Confluence · complete Rust port roadmap

The production target is a three-lane team match with selectable epic-inspired heroes, bot practice, authoritative online play and an original art direction. The proposed first team-parity milestone is **3v3**, because the existing browser game supplies six-seat behavior, bot and balance fixtures. The existing desktop target remains **6v6** and the deferred mobile plan specifies **5v5**. Each team size needs its own lane density, roster, frame-time and network tests. Two Rust modes are playable. Confluence has enhanced Rama and Hanuman kits, moving armies, solo play and an opposing-seat private match. Sangam City’s local Rust sparring mode runs all 14 classic kits and their original skinned rigs. A tested system below counts for the named executable, version and workload. ## How to call the port complete

1. **Gameplay acceptance.** Every intended hero starts, moves, attacks, contributes to an objective, dies, respawns and can finish a match under both native and Wasm authority. Every accepted balance difference identifies its mode, rule revision and replay. A public registry of hero IDs names their actual roles, supported inputs, clips and verified targets.
2. **Team acceptance.** Independently controlled parties join the agreed team size, recover a disconnected seat, play to a result and rematch on the deployed host. Bot practice runs under the same rules. Publish reproducible replay/economy checks plus measured bandwidth, server tick deadlines and client correction behavior from a real network.
3. **Presentation acceptance.** Compare representative captures with the original key art for each hero, including the face, hands, equipment, signature motions and readable threats in a crowded lane. Production art and animation review and hardware performance are separate recorded results. A successful rig export, practical CPU pose oracle or loopback network soak alone cannot establish a commercial game's production quality.
4. **Release acceptance.** Ship the selected platforms with tested first launch, upgrade, settings migration, failure recovery, notices, verified downloads and documented deployment/rollback. Publish only the platforms and features exercised in that release. Preserve working ANDOLAN city links, saves and deployments separately.

The first parallel batch is A1–A3, the roster/asset inventory portion of B2, six-seat admission fixtures for B5, and a reproducible profiling scene for C1. The first integrated review should join A1's semantic inputs, A2's surface identity and A3's camera ray to the existing Hanuman/Rama replay. That makes subsequent traversal, hero, objective and room work independently testable without replaying the repository's entire history.
