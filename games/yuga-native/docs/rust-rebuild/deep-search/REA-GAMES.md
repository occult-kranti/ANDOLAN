# Games recovered from the REA community and adjacent project indexes

25 November 2026. **GunZRs and Snowball War are the two strongest Rust leads for Hanuman.** GunZRs has an actual Bevy skeletal playback system with a separate upper-body layer. Snowball War has an asset-independent combat simulation whose 18 upstream tests passed twice in this workspace. Their original games, data formats, units and art direction are different from YUGA's. The usable parts are the software and the fixtures described below.

## What the searches covered

- Read the pinned root tree and README of **56 unique repositories**, including 29 projects selected from the 89-repository public account of a verified REA fork owner. Recorded all 56 README hashes, available top-level license texts, progress files where obtained, and large-tree truncation flags. A root-tree read confirms listed paths only. [Primary evidence](rea/primary-source-index.json)
- Ran **16 upstream PR queries** and **four repository queries**. Each captured the first ten matches at default relevance, reported total and incompleteness flag. Confirmed two PR heads and their source relationships independently. These queries supplement the prior 4,000-name snapshot and 45-fork branch sample. [Exact queries and results](rea/search-receipts.json) · [Previous branch research](../REA-AND-REBUILDS.md)
- Recounted eight categories in a curated game directory. **103 titles and 140 project rows** match its headings. Retained title, project and source links for every row, including projects with only showcase links. Another index contains **6,067** rows covering emulators, tools and games. Its 845 engine-reimplementation rows have a separate searchable index with names, URLs and listed languages. Rust is a useful filter. Source review at the chosen revision still decides whether the code is suitable. [Title and category index](rea/curated-title-index.json) · [845 engine leads](rea/engine-rebuild-index.tsv)
- The a-barzanti directory now contains a metadata manifest of 84 projects in seven categories. Another curator described it as a repo of community browser rebuilds. Its current tree and manifest take precedence. A directory and a game implementation are different contributions. [Manifest](https://github.com/a-barzanti/ai-rebuilds/blob/e073d8f1908e9ed7402349f6beb8f64890ef80cd/data/projects.json) · [103-title source](https://github.com/HaozheH3/awesome-rea-games/blob/4316a4ce86fdd851f0180ffee87dc336851bf5b6/README.md) · [6,067-row source](https://github.com/alexgaoth/awesome-reverse-engineered/blob/431707fd4f9b4419f2869707416d1df59a1b9412/categories/game-decompilations-reimplementations.md)
- The quoted queries for Overwatch, Dota, Valorant, Team Fortress, Pokémon and FireRed yielded zero upstream PR matches. The Deadlock query returned 13 text matches and showed ten, predominantly process/lifecycle results. “Map format” produced 107 results, including JavaScript **source maps**. The broad “rea-agents + game” query estimated 119,375 repositories, and “with REA” also matched React. These controls explain why keyword counts alone cannot identify a reconstructed game. No inspected source established a complete REA reconstruction of Deadlock, Overwatch, Valorant or Dota 2. [Search receipts](rea/search-receipts.json)

### Direct REA work versus adjacent cases

PR 7186 is an unmerged non-default branch of the direct fork `8rulerstar/rea`, pinned at `29950bd`. Its Unity Addressables code inventories content catalog records. YUGA could borrow its **packaging QA approach** to identify missing map, material and animation references before release. The fork implements inspection tooling. PR 876, by contrast, was merged from an upstream branch of morluto/rea and documented DX-Ball; the game source lives in a different repo. The earlier ANP3 and Unity SerializedFile PRs remain independent examples. [Addressables branch](https://github.com/8rulerstar/rea/blob/29950bd8471fbd789ad4a30196726e0334551f5f/src/application/unity/UnityAddressablesService.ts) · [PR 7186](https://github.com/morluto/rea/pull/7186) · [PR 876](https://github.com/morluto/rea/pull/876)

## Repeat the gameplay control

This probe obtains the exact seven upstream simulation modules and the unmodified integration test from Git. A temporary crate root exposes those modules to rustc. Both runs with rustc 1.88.0 passed the same 18 tests with no original game data. They cover acceleration, arena clamping, timed spawns, projectile arcs and expiry, target overlap, close-up animation selection, round restart, input debounce, power-ups and repeatable seeded simulation. The SDL renderer, audio and original executable were outside the test. [Probe](rea/probe-snowball.py) · [Digests and named passes](rea/snowball-test-result.json)

```bash
git clone --filter=blob:none --no-checkout https://github.com/tuunanet/rea-ski-or-die-reconstruction.git /tmp/yuga-snowball
python3 games/yuga-native/docs/rust-rebuild/deep-search/rea/probe-snowball.py /tmp/yuga-snowball /tmp/yuga-snowball-result.json
```

To repeat the discovery at a later date, run the exact queries in the search receipt using the same page size. Results will move as GitHub changes. For the immutable catalogs, fetch their README or category text by commit and verify the SHA-256 in the title index. The counts above are separate searches and overlapping sets. Adding them together would overstate coverage. A project should move from “found” to “candidate” only when a specific code file resolves a YUGA problem and a local fixture illustrates how its behavior differs from the existing implementation.
