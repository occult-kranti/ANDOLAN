# Rebuilding YUGA in Rust

**25 November 2026.** The first playable Rust build is Hanuman’s solo drill on Confluence. It reuses the production map, animated hero, soldier models, kit definitions and audio. Rust resolves player movement, casts, shields, health, collision and victory at 20 Hz. The native terminal and the browser run the same rules. The browser reuses YUGA’s PlayCanvas renderer, while Godot supplies a running comparison for the migration. The multiplayer match and complete hero roster remain in the migration backlog. [Play or build the drill](../../../yuga-rust/README.md) · [Download](../../../yuga-rust/downloads/yuga-rust-practice.zip?raw=true)

## Two additional Rust engine comparisons

The moderator also inspected these independent engine projects at the revisions below. Their source was read for these decisions. Neither engine nor either commercial game’s media is packaged with YUGA.

- **OpenPAL3, the Rust reimplementation of The Legend of Sword and Fairy 3.** Its role controller stores patrol targets and supports both loop and ping-pong policies. Confluence waves travel to an enemy objective, so the useful part is the explicit route cursor and terminal policy. Its transport system carries a rider with an owning platform and only accepts an exit on a valid navigation layer with border clearance. Apply that distinction to a possible ferry or moving Lanka platform. Build a YUGA test for disembarking on the same XZ but wrong height before attempting a ferry. The upstream README requires separately supplied original game data. GitHub identifies the project as GPL-3.0. [Role controller](https://github.com/dontpanic92/OpenPAL3/blob/8d14da87988308e8844f7cb567588ad5b7236099/yaobow/shared/src/openpal3/scene/role_controller.rs#L335-L384) · [Rider and exit](https://github.com/dontpanic92/OpenPAL3/blob/8d14da87988308e8844f7cb567588ad5b7236099/yaobow/shared/src/openpal3/scene/scene.rs#L929-L962) · [Project and data](https://github.com/dontpanic92/OpenPAL3/tree/8d14da87988308e8844f7cb567588ad5b7236099)
- **Vault13, a Rust reimplementation of the Fallout 2 engine.** Its movement sequence emits an object-moved event at a tile crossing. A cancellable sequence hands a separate handle to the owner and terminates future updates after cancellation. That is a concrete reference for publishing lane crossings and cancelling a minion’s pending action on death. Its per-frame sprite shifts and hex topology do not match Confluence. Its source also calls out unresolved blocker replanning. Make a new blocking wall and an emptied target lane explicit failed-route cases for our bots. The project calls the game incomplete and uses separately supplied Fallout 2 data. GitHub identifies the project as GPL-3.0. [Movement and crossing](https://github.com/pingw33n/vault13/blob/9add0692571c941b6aa771bfc893d52e3198629e/src/game/sequence/move_seq.rs#L87-L182) · [Cancellation](https://github.com/pingw33n/vault13/blob/9add0692571c941b6aa771bfc893d52e3198629e/src/sequence/cancellable.rs#L39-L63) · [Project status](https://github.com/pingw33n/vault13/blob/9add0692571c941b6aa771bfc893d52e3198629e/README.MD)

## Roadmap to a complete Rust game

Confluence already has a native single-player game, a TypeScript multiplayer authority and Blender source art. The following sequence reuses those assets and observed rules. The first three open workstreams can proceed in parallel. The moderator integrates their outputs against the same map revision, event IDs, coordinate system and build digest before moving the match over. The broader production roadmap still owns art, desktop and roster acceptance. [Full game roadmap](../FULL_GAME_PRODUCTION_ROADMAP.md)

| --- | --- | --- |
