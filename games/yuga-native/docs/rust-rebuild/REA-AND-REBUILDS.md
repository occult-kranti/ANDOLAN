# What the REA forks and Rust game rebuilds offer YUGA

Research checkpoint, 25 November 2026. For Hanuman, the best immediately usable result is a tested way to replay and check a small Rust simulation module without game assets. For the three-lane map, the most useful precedents are a room format with stable instance IDs, a distance-parameterized path, and a parser that rejects a bad vertex reference. None supplies a production Hanuman rig or an authored Confluence map. The following decisions identify the specific code and what would justify integrating it.

## Repeat the measurements

Use a checkout that contains the pinned commit. The probe extracts the single module into a temporary directory, checks its SHA-256, compiles it with rustc, runs the binary two times, and compares both results. It requires no game client or proprietary input. Six nonzero seeds produced 6,144 successfully replayed outputs across two generators after save/restore. Two zero-seeded generators returned zero throughout 512 steps each. Over 1,024 calls, the observed counts for 0, 1, 2, 3 and 4 were 210, 190, 202, 205 and 217. The inputs exercise those edge cases; they are not a statistical quality or multiplayer determinism certification. [Probe](rea/probe-doukutsu-rng.py) · [Receipt](rea/doukutsu-rng-check.json)

Run from the ANDOLAN root with `git`, `python3` and `rustc` on PATH. The separate fork continuation uses an authenticated GitHub CLI and writes to a fresh path.

```bash
git clone --filter=blob:none --no-checkout https://github.com/doukutsu-rs/doukutsu-rs.git /tmp/yuga-doukutsu
python3 games/yuga-native/docs/rust-rebuild/rea/probe-doukutsu-rng.py /tmp/yuga-doukutsu /tmp/yuga-rng-receipt.json
python3 games/yuga-native/docs/rust-rebuild/rea/list-forks.py /tmp/rea-next.json --after 'Y3Vyc29yOnYyOpHOVCTtGw==' --pages 5
```

## Five panel rounds

1. **Discover.** Pin the upstream tree, follow its game evidence pages, and query public direct forks. Record branch tips independently of game cases.
2. **Qualify.** Compare 12 fork heads. Separate game, dependency, owner association and implementation language. Read Rust manifests, licenses and module files before proposing adoption.
3. **Exercise.** Compile the real MIT donor module. Preserve the successful replay trace and the inclusive upper bound and zero-seed counterexamples.
4. **Challenge.** Test the native ground fixture. Reject the tile-to-ground coordinate transplant against the existing distance-plus-height rule. Keep 3D height as an explicit ability-port gate.
5. **Decide and hand off.** Keep the probe and fork census as reusable tools. Advance typed animation cues and map validation behind the tests above. Acquire a demonstrable on-rig clip and a same-height/overhead gameplay fixture before describing the donor study as hero or combat parity.

## Follow-up on changed forks and non-default branches, 25 November 2026

The default-branch sample missed useful work. A second query sampled the 20 most recently updated direct forks, the 20 most recently pushed, the five most starred, and the two game-associated owners. The 20-star query failed, so the starred stratum reuses the successful five-result response. After deduplicating, **45 repositories** returned **300 branch refs** from one REST page per repository. Eight pages reached the cap of 30. The 300 refs pointed to **135 distinct commits**. Relative to the pinned upstream main, 114 tips had diverged histories, four were ahead, 16 were behind and one was identical. Across these refs, 22 repositories had a tip containing commits absent from pinned main. Mirrored branches and pending upstream work can produce these counts.
