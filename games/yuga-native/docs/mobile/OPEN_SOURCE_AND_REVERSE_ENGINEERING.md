## Rejected shortcuts and the MLBB source question

The inspected [Shotcaller license](https://github.com/spicylobstergames/shotcaller-godot/blob/37dcfa91f15ca34b8eeb5cbab74b450a7326d457/LICENSE.md) assigns **PolyForm NonCommercial 1.0 to code and CC BY-NC to media**. Its README's statement that a future shared engine layer “will be licensed as MIT or similar” does not grant that permission to this revision. It is source available; reject its current code/art as the permissive foundation for this production game. A selected lane-goal source file was read, but no code was adopted.

[MOBA-ActionMagic](https://github.com/naumnek/MOBA-ActionMagic/tree/88fd5b8996ae97c610cfe9b754267a219557d6cc) really describes an Android-targeted Unity project. Its inspected tree has no root game license, and `Assets/license.txt` states Unity Companion License. That does not establish a Godot-reusable complete game or permission for all bundled assets. [The Godot MOBA course repository](https://github.com/ColinGilbert/godot-moba/tree/a4fbe608ff94c302e043878bbec5a74b4436545e) likewise has no root game license in its inspected complete tree; a Git addon license covers the addon. Its README says lightmaps were omitted. Both are rejected as currently proven reuse sources.

**No credible, complete, reusable Mobile Legends: Bang Bang source was established in this bounded search.** Three MLBB-oriented queries returned mod-menu/external projects, region/API/hero-metadata tools, websites and unrelated results. Four broader MOBA queries supplied the examples above. Each query inspected only its first ten relevance-ranked repository records; this is not proof that no source exists anywhere. A GitHub title, detected MIT/GPL badge or public dump cannot establish original authorship, a complete build, server code or rights to commercial characters and assets. Mod-menu code, attached archives and commercial clients were not downloaded. No anti-cheat work was performed.

A “complete source” candidate would need an identifiable authorized publisher, exact revision and file inventory, scoped code/dependency/asset terms, reproducible client and server builds, required data, and an independently executed original game path. Missing server logic cannot be recovered from a client that never contained it. This gate presently admits none of the sampled MLBB claims.

## Reproducible next experiment: our own Android APK

This is a proposed execution packet, **not an executed result**. Use a new original tiny Godot fixture, not the full hero/world or a downloaded commercial client. It isolates tool feasibility before taking the main mobile build lane.

1. **Freeze known inputs.** Pin fixture commit, original source and assets, Godot 4.6.3 binary/export-template hashes, export preset, Android packages, compiler and dependency notices. Record package ID, ABI, build flags and public signing-certificate digest; retain keys outside evidence. The [official 4.6 export document](https://github.com/godotengine/godot-docs/blob/b10b7ed373c2d15555186914b82e167169b5b87b/tutorials/export/exporting_for_android.rst) recommends JDK 17, SDK Platform/Build Tools 35/35.0.1 and NDK 28.1.13356709 for its described setup. Select exact packages/templates for the actual fixture, inspect what already exists, and reserve the serialized build/analysis lane before installing or running it.
2. **Build a meaningful owned native subject.** The fixture has original touch/deadzone and cooldown rules with explicit expected outputs. For ELF analysis, add a tiny experimental original native library/GDExtension exposing a selected C entry such as `yuga_mobile_deadzone`; pin the native source, generated bindings and dependencies. Keep a symbol-bearing build and an optimized/stripped sibling, including debug-symbol/build-ID mapping. Do not move production GDScript into native code merely to create a decompiler demonstration.
3. **Inventory the owned APK.** Hash the APK and signature/certificate, list exact ZIP members with sizes/digests, reject duplicate/noncanonical/traversal member names and oversized expansions, then extract only allowlisted owned `lib/arm64-v8a/…so` inputs into a fresh path. Record ELF machine/class, build ID, dependencies and symbol availability. Use `apkanalyzer`/Android tooling for wrapper and manifest metadata once installed; no parser is qualified by this document. Treat packaged scripts/data and DEX/Java wrapper metadata as separate from native ELF analysis.
4. **Run the existing bounded analyzer on one exact ELF.** Reserve a CPU/memory slot; retain stdout/stderr, exit codes and provider/input identities. A prepared invocation from repository root is shown below. The selected symbol must be present; if stripping removes the selection, retain that failure and review a bounded address-selection adapter instead of quietly analyzing a different binary. The previous x86-64 result does not waive this ARM64 gate.
5. **Challenge the reconstruction on owned hardware/runtime.** An independent worker derives a small implementation from the selected pseudocode/assembly and compares it with the original source contract and actual ARM64 oracle calls. Include exact deadzone boundaries, cancellation/restart, repeated touch identifiers, cooldown limits and declared nonfinite-input handling. Retain a deliberately altered threshold or constant as an expected failing control. Report value tolerances, compiler flags and the selected function's coverage; do not turn a few passing calls into whole-APK equivalence.
6. **Measure the actual product separately.** A physical-device fixture must demonstrate simultaneous move/aim/cast, lifecycle pause/resume, orientation/safe-area behavior and declared frame-time/thermal/battery observations. A tiny native oracle, emulator pass or software-rendered screenshot is not acceptance of YUGA's hero/world, networking, battery life or commercial-game visual quality.

## Public reference observations and adoption gates

For commercial mobile references, first record accessible official demonstrations or user-owned recordings: title/version, device when known, URL/date and exact timestamp, interaction attempted and visible outcome. Measure only what can be seen—control placement, aim/cancel feedback, HUD density, loading transitions, camera framing. Label inferred rules and timing uncertainty. No new commercial mobile footage was watched in this pass, so this document contains no such measured observations.

Turn those observations into an original YUGA behavior specification and tests. An implementer should receive that specification and appropriately licensed selected code, not extracted commercial assets or speculative “recovered” internals. This separation supports provenance; it does not automatically certify a legally formal clean-room process. No anti-cheat circumvention, decrypted client dumping, authentication bypass, unlicensed asset extraction or distribution is part of the proposed work.

Every adoption must pass: exact revision/file hashes; actual file-scoped license and origin review; separate asset/dependency terms and notices; one named product defect addressed; isolated compatible build; a concrete negative test; current input/lifecycle/authority regression checks; rollback path; and independent review of the resulting artifact. Performance claims require named hardware and raw measurements. Research/reference status changes only when those gates produce fresh evidence.
