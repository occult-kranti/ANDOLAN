# Deadlock: public engineering evidence and original YUGA experiments

Inspected 16 October 2026 UTC. This pass found real replay parsers, analytics implementations, a small independent lane-game prototype and an already-hosted Reddit archive. It **did not recover Deadlock's game engine**. No commercial executable, replay, extracted model, animation or proprietary source was supplied or downloaded. No Deadlock match/video was watched. The only reference code executed was a small inspected MIT analytics function on synthetic inputs, plus REA's inert TypeScript analysis.

Selected files and immutable URLs/hashes are in [DEADLOCK_SOURCES.json](DEADLOCK_SOURCES.json). Downloads remain under `/workspace/research/yuga-deadlock`, outside the product. No reference code, dependency, game constants or assets were added to YUGA. Repository files were treated as evidence, not setup instructions.

## What transfers, and what does not

**Keep reward sources and event identity distinct.** The API's [economy definitions](https://github.com/deadlock-api/deadlock-api/blob/917e8537cb256cffd1417a56737adfed47370dd1/website/src/components/features/games/economy-definitions.ts) separate directly confirmed income from orb income and subtract assists from a category that otherwise includes them. Boon's [dataset code](https://github.com/pnxenopoulos/boon/blob/0c7663f17aa24a65374925b022fd4d98aaa47477/crates/boon-python/src/datasets.rs#L250) retains per-source gold/orb totals and distinguishes snapshot values from scoreboard last-hit totals. This supports a data-model lesson, not copying Deadlock's reward formula. YUGA already has authoritative `gold`/`camp`/`buff` events, shard IDs, actual `sharedAwards`, and secure/steal labels. Its next acceptance question is whether one ledger reconciles every recipient's wallet change without counting a shared award and a later shard claim twice.

**A source code comment can be stale even inside a current tool.** Haste's parser comments describe a fixed Deadlock tick interval, but the code reads `tick_interval` from server information. The API's later [tick finalizer](https://github.com/deadlock-api/deadlock-api/blob/917e8537cb256cffd1417a56737adfed47370dd1/live-events/src/demo_parser/visitor.rs#L389) explicitly warns about a different interval in one replay build and mid-match streams without a synchronization command; it computes game time after subtracting paused ticks and the game-start offset. We did not measure Deadlock's current tick rate. For YUGA, protocol/tick/time/session identity must be explicit; a reconnect or pause must not be reconstructed from wall time or an assumed competitor rate.

**Report uncertainty in sparse analytics.** The API's [soul-lead helper](https://github.com/deadlock-api/deadlock-api/blob/917e8537cb256cffd1417a56737adfed47370dd1/website/src/lib/tracker/soul-lead.ts) unions sample times, sorts copies, carries the last known player values forward and estimates time ahead by linear interpolation. Our synthetic probe reproduced this, including a sparse example reporting `aheadShare=1` while the opposing team's first recorded sample arrives later. That is an explicit modeling assumption, not proof that the team led throughout unobserved time. A future YUGA economy graph should label missing/old samples and derived intervals rather than present an interpolated statistic as an exact event history.

**Combat state and presentation have different jobs.** The API's [event types](https://github.com/deadlock-api/deadlock-api/blob/917e8537cb256cffd1417a56737adfed47370dd1/live-events/src/demo_parser/types.rs) distinguish entity changes, kills, combat-log messages, pickups and completed ticks. Boon classifies light/heavy/other melee from explicit flags rather than guessing from damage amount or ability name. These are community decoding choices, not proof of proprietary engine order. YUGA's shot acceptance, release, collision, reward and animation cue should remain separately inspectable. Existing real GLB/root/contact checks are relevant original tests; no inspected source establishes a Deadlock blend tree or animation timing to copy.

**Use the independent prototype as a counterexample, not a specification.** [Onda](https://github.com/Mvfm-25/Deadlock-Manager/blob/c9252f69aac9088fee7151c883d7a4f91d98f51c/deadlock-manager/scripts/onda.gd) advances a shared formation anchor, stops it when any living member has a target, and respawns the whole wave after the last member dies with increasing delay. [Minion](https://github.com/Mvfm-25/Deadlock-Manager/blob/c9252f69aac9088fee7151c883d7a4f91d98f51c/deadlock-manager/scripts/minion.gd) guards death against duplicate emission, re-evaluates dead targets and puts guardians last in target priority. Its hit radius follows sprite dimensions and damage is applied directly on a timer. YUGA should retain its own independent authoritative colliders/projectiles rather than couple new model scale to damage. Useful tests are simultaneous lethal hits yielding one death/reward, re-targeting after death, and symmetric lane pressure under mirrored seeds. No inspected prototype code supplies public matchmaking, network reconciliation or current commercial wave rules.

## Already-hosted Reddit archive appendix

The pinned `deadlock-daily` tree contains **87 raw JSON filenames dated July 17–October 16, 2026**, with missing dates August 17/22, September 19 and October 6/15. This is filename coverage, not proof of complete daily capture. The README claims 100 Hot posts per day, QClaw-driven collection and generated Chinese summaries. No collector source or acquisition log was present in the inspected tree; its only workflow was a deployment file, which was not executed.

The July 17, September 16 and October 16 JSON files each contain 100 rows, totaling 300 distinct permalinks. Their fields are only title, author, ID, posting timestamp, votes/score and comment count: **no selftext or comment bodies**. Older posts can appear in a later snapshot. Four sampled rows had negative comment counts. We cannot validate the archive's acquisition method, authenticity against the original Reddit responses, deleted/edited history, or count accuracy from these files. Hot ranking and date selection also preclude prevalence estimates.

[Archive audit](DEADLOCK_ARCHIVE_AUDIT.json) contains exact snapshot hashes/URLs and eleven paraphrased title-level research leads with original permalinks. It omits author values and raw text. Those leads are weaker than subsequently retrieved official post/comment text and should not be described as full reviews. Generated summaries are secondary interpretation, not additional independent participants. No GitHub workflow, relay/proxy, archive script or alternate Reddit endpoint was executed for this archive study.

After the current gameplay freeze, run one original YUGA two-client camp-and-shard scenario while recording authoritative event ID, simulation tick/time, source, actual recipient amounts and before/after balances. Include simultaneous claims, one claimant disconnect, shard expiry, a camp reset and replay. Require exactly-once payout, no payout for expiry/reset, consistent reconnect identity and agreement between receipt and wallet. Capture the native HUD and attack-release timestamps alongside that ledger. Then ask a first-time observer to explain who earned what; correctness alone does not establish comprehension.

No new backend dependency is justified by these sources. The existing TypeScript authoritative simulation/WebSocket server remains the concrete implementation under test. Further commercial-game reconstruction requires an appropriately licensed, version-identified input and an explicit question; public parser source alone does not establish proprietary netcode, exact reward balance, animation graphs, anti-cheat or matchmaking.
